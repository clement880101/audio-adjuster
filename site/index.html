How it works

No public API for this exists.

So it is built from the one primitive that does: a private Core Audio process tap that captures an app's audio and mutes its normal path, re-rendered at whatever level you chose.

Opt in, per app

A tap is created only for apps you actually adjust. Everything else keeps its ordinary audio path, untouched and with no added latency.

Restores itself

The tap mutes an app only while our render loop is reading it. Stopping is a complete restore — there is no state left behind to repair.

Calls behave

macOS quietens other audio during a call, and that still happens. But tapping the call itself would cost it its own exemption, so that much is measured and cancelled — enough for its bar to work.

The controls

One bar per app. That is the whole thing.

0 to 1000%

100% sits at the midpoint. Below it the scale is linear, so cuts are proportional and reach exact silence. Above it logarithmic, so every equal drag is an equal multiplication rather than a sliver of useful range and a long useless tail.

Linked, or not

By default, turning one app up turns the others down by the same total, so the mix keeps a constant sum. Switch it off and each bar moves alone. Mute is never linked either way — it stays the way to silence one app and nothing else.

Only what you hear

Apps that have actually made a sound, and they keep their place once they fall quiet, so a volume is still reachable between tracks. An app's several audio processes collapse into one bar. System chimes never appear.

Claims about audio in this project are measured rather than assumed — the ducking figures, the gain linearity, the compensation convergence. They live in the README with the numbers attached.

Worth knowing

It asks for audio-recording permission. Process taps are gated behind it. The app reads each app's audio in order to play it back at your level, and records nothing — but grant it and a tap returns digital silence rather than an error, which is a confusing way to fail.

The build is ad-hoc signed, not notarized. The project has no Apple Developer ID, so macOS cannot verify who built it. Installed with the command on the left it opens normally — files fetched by curl are not quarantined. Downloaded through a browser it is, and macOS will refuse a double-click: open it the first time with right-click → Open, read the warning, and decide for yourself. Building from source sidesteps the question.
